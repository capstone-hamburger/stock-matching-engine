# 호가 스냅샷과 Market Data Publisher

백엔드는 종목을 한 번 구독하면 기본 5초마다 매수·매도 상위 5개 가격대의 전체 스냅샷을 받는다. 같은 가격에 대기 중인 주문은 한 줄로 합산한다. 예를 들어 10,100원에 3주와 4주가 매도 대기 중이면 매도 1호가의 잔량은 7주다. 그중 2주가 체결되면 다음 스냅샷에는 5주가 표시된다.

## 백엔드에서 구독하기

기존 WebSocket에 연결해 다음 JSON을 text 메시지로 보낸다. 기본 주소는 `ws://127.0.0.1:9002/`다.

```json
{"type":"SUBSCRIBE_ORDER_BOOK","stockId":1001}
```

라우터가 해당 연결의 구독을 등록하면 다음 응답을 보낸다.

```json
{"event":"ORDER_BOOK_SUBSCRIBED","stockId":1001}
```

이후 서버의 발행 틱마다 다음 형태의 메시지를 받는다. 매 틱의 `bids`와 `asks`로 해당 종목의 호가창 전체를 교체한다.

```json
{
  "event": "ORDER_BOOK_SNAPSHOT",
  "stockId": 1001,
  "bids": [{"price": 10000, "quantity": 8}, {"price": 9900, "quantity": 3}],
  "asks": [{"price": 10100, "quantity": 5}]
}
```

| 필드 | 의미 |
| --- | --- |
| `stockId` | 서버가 담당하는 종목 ID |
| `bids` | 매수 가격 내림차순. 첫 항목이 최우선 매수호가 |
| `asks` | 매도 가격 오름차순. 첫 항목이 최우선 매도호가 |
| `price`, `quantity` | 지정가와 해당 가격의 총 미체결 잔량. 둘 다 JSON 정수이며 잔량 합계는 int64 범위 |

한쪽에 다섯 가격대 미만이면 존재하는 가격대만 보내고, 비어 있으면 빈 배열을 보낸다. 주문이 없는 틱에도 최신 스냅샷을 발행한다. 같은 연결에서 주문과 구독을 함께 사용하면 스냅샷이 요청과 응답 사이에도 도착할 수 있다. 백엔드는 `event`로 분기하고, `ORDER_BOOK_SNAPSHOT`을 읽어도 대기 중인 요청은 유지한다.

구독은 연결 단위다. 같은 연결에서 다시 구독해도 스트림은 하나다. 연결이 끊기면 새 연결에서 다시 구독하고 다음 스냅샷으로 복원한다. 잘못된 구독 필드는 `INVALID_REQUEST`, 서버가 담당하지 않는 종목은 `UNKNOWN_STOCK`으로 응답한다.

## 같은 연결에서 구독 해제하기

스냅샷을 받던 연결에서 다음 요청을 보낸다.

```json
{"type":"UNSUBSCRIBE_ORDER_BOOK","stockId":1001}
```

라우터는 해당 연결의 구독을 해제하고 전송 대기 중인 스냅샷을 버린 뒤 응답한다. 이미 쓰기를 시작한 스냅샷은 이 응답보다 먼저 도착할 수 있다.

```json
{"event":"ORDER_BOOK_UNSUBSCRIBED","stockId":1001}
```

확인 이후에는 같은 연결에서 다시 구독할 때까지 스냅샷이 오지 않는다. 이미 해제했거나 구독한 적이 없어도 같은 확인 응답을 받는다. 주문·조회는 계속 처리되며 서버의 발행 타이머와 다른 연결의 구독은 유지된다. 필드와 종목 검증은 구독 요청과 같다.

## 갱신과 전송 흐름

1. 엔진이 신규 주문을 처리하면서 가격별 미체결 잔량을 갱신한다. 한 주문으로 여러 건이 체결되면 모든 체결과 신규 주문의 잔량 등록을 먼저 끝낸다.
2. 라우터의 엔진 Worker는 주문이 접수되거나 취소가 성공할 때마다 `MarketDataPublisher::refresh()`를 호출한다. Publisher는 `Engine::orderBook(5)`로 각 방향에서 최대 다섯 가격대만 읽어 메모리의 최신 스냅샷을 교체한다. 전량 체결이나 취소로 빈 가격대가 사라지면 뒤의 가격대가 올라온다.
3. 같은 Worker의 `steady_timer`가 만료되면 Publisher가 저장된 스냅샷을 라우터 콜백에 넘긴다. 갱신과 틱이 순차 실행되므로 한 주문의 체결 중간 상태가 발행되지 않는다. 기본 주기는 5초이며 `RouterConfig::marketDataInterval`에 양수 밀리초 값을 지정해 바꿀 수 있다.
4. 라우터는 틱마다 JSON을 한 번 직렬화하고 I/O 스레드에서 구독 중인 세션으로 전송한다. 세션당 WebSocket 쓰기는 한 번에 하나만 진행한다. 전송이 밀리면 대기 중인 스냅샷은 최신 한 건으로 교체하고 대기 중인 요청 응답을 먼저 보낸다. 따라서 느린 연결은 일부 틱을 건너뛸 수 있다.

스냅샷은 엔진 프로세스의 메모리에 보관한다. 서버를 재시작하면 빈 호가창으로 시작한다. 체결 내역을 정산할 때는 주문 응답의 `trades`를 사용한다.

## 검증

`cmake --build --preset dev` 후 `ctest --preset dev`를 실행한다. WebSocket 통합 테스트는 짧은 틱으로 빈 호가의 반복 발행, 양방향 5단계 정렬, 동일가 잔량 합산, 연속·부분 체결 및 취소 후 6순위 승격을 확인한다. 한 연결에서 구독을 해제한 뒤 다른 구독자에게 갱신분이 도착하는지, 해제한 연결에서 주문·조회와 재구독이 가능한지도 검증한다.
